# 安装与验证

面向：拿到 `app-debug.apk` 后，用数据线在安卓手机上装好并逐项确认功能正常的人。

功能：教务导入（可记住账号密码，**学期自动试**）· 今日课表 · 多周周课表（**左右翻页 + 连堂合并 + 点课看详情**）· 上课前 **10/20/30 分钟、1 或 2 小时**弹横幅提醒（含厂商适配自检面板）· 桌面小组件（**不限机型，带预览图与按机型的手动添加步骤**）· **全局自定义背景（含手动挑显示区域）** · **作者署名与免费声明** · **崩溃报告与自检诊断**。

本版说明：**导入不再假设「课表页上默认选中的学年学期是对的」**。那个默认值可能是上一学年（实测遇到过服务端把上一学年的第 2 学期渲染成选中状态，而学生真正有课的是下一个学年），且服务端没有任何「当前学期」字段可用。现在导入会**按候选顺序自动试几个学期**（先试按本机日期算出的当前学期，再试页面默认值、同学年另一学期、上一学年两个学期），第一个真有课的就算数；导入与刷新的提示里都会带上**最终用的学期名**。详见下面第三节第 0 条。

本版说明三：**新增两件事 —— 自己加课、手动锁作息档位**。①周课表右上角多了一个「**+**」：临时调课、补课、换教室，手动选好星期 / 节次 / 周次就能塞进表里，可以只加某几周，也可以加满整个学期（1-19 周）。自己加的课在格子上有一道**深色描边**（正式课没有），点开能改能删；它存在**单独的文件**里，重新导入课表、或者换一门课导入，都不会被冲掉。②「⋮」菜单里多了「**作息时间**」：默认还是按日历月份自动切（5-9 月夏令、10-4 月冬令），但学校临时调整作息时，可以在这里**固定成冬令或夏令**，不再看月份。第 1-5 节两季本来就相同，受影响的只有第 6-12 节，所以对话框里拿**第 6 节**给你看当前档位下的实际时刻。详见下面第二节的「自己加课」和第三节的「作息档位」两条。

本版说明二：**修掉了左侧时间轴「时间显示不全」**。那一格原来的写法是 `Column(Modifier.height(54.dp)) { Text("第N", fontSize = 10.sp); Text("07:50", fontSize = 9.sp) }` —— 高度被**锁死**成每格 54dp，两个 `Text` 又都没写行高，于是都从主题的 `bodyLarge` 继承了 24sp。后果是 Column 分给第二个孩子的高度只剩 `54 − 24×字号`：**系统字号调到 1.15 倍以上，`07:50` 就被从下往上裁掉一截**（`第N` 自己只要 24sp、永远够用，所以只有时间会出事），看上去就是「时间显示不全」；再大一点（约 1.6 倍）连列宽都不够，`07:50` 还会折成两行、和相邻几行的字叠在一起。现在行高**显式写成 12sp / 11sp**（合计 23dp，离 54dp 还远），列宽也从写死的 40dp 改成**按当前字体实测**（40–72dp 自适应），再配 `maxLines = 1` 兜底。**默认字体下的观感与之前完全一致**（宽度按下限兜住，不会变窄），只有把系统字号调大时才会看到时间轴自己变宽。详见下面第二节「周课表」里关于时间轴的那一条。

## 一、准备

### 1. 手机侧

- 安卓 **8.0（API 24）及以上**
- 打开「开发者选项」→「USB 调试」（设置 → 关于手机 → 连续点 7 次「版本号」）
- 用数据线连电脑，手机上弹出「允许 USB 调试吗？」时点**允许**（建议勾选「一律允许」）
- 小米/红米还需额外打开「USB 调试（安全设置）」，否则 adb 装包会被拒绝；华为/荣耀需打开「仅充电时允许 ADB 调试」

### 2. 电脑侧

需要两样东西：**adb**（随 Android SDK 的 platform-tools 一起装）和一份**自己构建出来的 APK**（见下面「重新构建」）。

把 adb 加进当前会话的 PATH（每次开新窗口都要做一遍；路径换成你自己的 SDK 位置）：

```powershell
$env:Path += ";D:\toolchain\android-sdk\platform-tools"
adb version
adb devices
```

`adb devices` 应该列出你的手机（形如 `XXXXXXX	device`）。
如果显示 `unauthorized`，说明手机上还没点「允许」，重新插拔一次；
如果显示 `offline`，执行 `adb kill-server` 后 `adb start-server` 再试。

## 二、安装

```powershell
adb install -r "app\build\outputs\apk\debug\app-debug.apk"
```

看到 `Success` 即安装完成。

> **注意**：debug 包的 applicationId 是 `com.ntu.schedule.debug`，与任何正式版（`com.ntu.schedule`）互不覆盖，可以共存。
> 若之前装过旧 debug 包且签名不一致，加 `-r` 也可能失败，此时先 `adb uninstall com.ntu.schedule.debug` 再装。

### 重新构建

```bash
# Linux / macOS
./gradlew assembleDebug

# Windows
gradlew.bat assembleDebug
```

产物固定在 `app/build/outputs/apk/debug/app-debug.apk`。

项目里带了 wrapper（`gradlew` / `gradlew.bat`），不用自己装 Gradle；`local.properties` 里要有 `sdk.dir=...` 指向你的 Android SDK（Android Studio 打开项目时会自动生成）。

> **国内网络**：如果卡在 `Downloading https://services.gradle.org/...`，把 `gradle/wrapper/gradle-wrapper.properties` 里的 `distributionUrl` 换成镜像（文件里注释了两个可用地址）；如果卡在下载依赖，`settings.gradle` 已预置阿里云镜像。

> 如果构建报 `Your project path contains non-ASCII characters`，把项目挪到**纯英文路径**下即可。

## 三、验证清单

按顺序做，每步都有明确的**通过判据**。建议对照真实课表（2026-2027 学年第 1 学期，14 条课程安排）核对。

### 0. 导入会自动试几个学期

**为什么要有这个**：导入一度停在「该学期没有查询到课程（2025 学年，xqm=12）」。原因是课表页上默认选中的学年学期**不是这个学生的当前学期** —— 服务端渲染的是 `xnm=2025` / `xqm=12`（2025-2026 第 2 学期），而这个学生下一年才入学，拿这组参数查 `kbList` 就是空的。真正有课的是 `xnm=2026` / `xqm=3`。

翻遍课表页与接口，**服务端确实没有一个可信的「当前学期」字段**（页面里没有脚本改写这两个下拉框；接口返回的 `XNM`/`XQM` 只是把问的参数原样回显，问哪学期就回哪学期）。所以现在的做法是**排候选逐个试**：

| 步骤 | 通过判据 |
| --- | --- |
| 正常导入 | 成功，且**底部提示里带上学期名**（如「导入成功，共 N 条课程安排（2026-2027 学年 第 1 学期）」）—— **务必核对它是不是你要的那一学期** |
| 看课程数 | 与教务系统上该学期的课程数一致 |
| 周课表对不对 | 第 1 周周一的日期与校历一致；课程时间落在正确的作息时刻里 |
| 导入后点「用已保存的登录刷新」 | 提示变成「已更新（2026-2027 学年 第 1 学期）」—— 也带学期名 |
| 万一真的没有课 | 提示会**列出试过的学期**：「没有查询到课程。已经试过 2026-2027 学年 第 1 学期、2025-2026 学年 第 2 学期…」，而不是那句让人看不懂的「该学期没有查询到课程（2025 学年，xqm=12）」 |

**已知代价（属正常，不是 bug）**：如果新学期还没排课，App 会退回显示**上一学期**的课表，并在提示里把那个学期名写出来。看到学期名不对就是这种情况 —— 等学校排完课再点一次「用已保存的登录刷新」。

**判据背后的道理**：`core/TermPicker.kt` 里候选顺序是「① 按本机日期算出的当前学期 → ② 课表页默认值 → ③ 同学年另一学期 → ④ 上一学年第二学期 → ⑤ 上一学年第一学期」，`ScheduleApi.fetchFirstAvailable` 第一个真有课的就是结果。遇到**登录过期或 HTTP 错误会立刻停**，不会接着试 —— 那不是换个学期就能好的事，继续试只会让你多等几个来回，还多撞几次学校的账号风控。

### 3. 今日课表

今天是 **2026 年 10 月 8 日 星期四**，第 6 周。对照真实数据，当天**恰好应显示两门课**：

| 节次 | 时间（冬令，10 月） | 课程 | 地点 |
| --- | --- | --- | --- |
| 第 1-2 节 | 07:50 - 09:20 | 高等数学B（一） | JX08-109 |
| 第 6-7 节 | 13:30 - 15:00 | 工程制图基础 | JX07-107 |

> 周四在真实数据里共有 4 条记录：高等数学B（一）1-2 节（5-18 周）、人工智能通识 4-5 节（JX02-206，**7-16 周**）、工程制图基础 6-7 节（JX07-107，5-16 周）、形势与政策 8-9 节（JX08-106，**仅 7 周与 15 周**）。
> **第 6 周不在 7-16 周也不在 {7,15} 周内，所以当天不应出现「人工智能通识」与「形势与政策」。** 这两条正好用来验证区间周次与离散周次解析是否都正确 —— 如果它们出现了，说明周次被当成了「全周」兜底。

判据：
- 每张卡片显示 `HH:mm - HH:mm · 第 X-Y 节`、课名、`地点 · 教师`、周次文本
- **第 6-7 节应显示 13:30 - 15:00**（冬令）。若显示 14:00 - 15:30，说明作息表取成了夏令 —— 这是本项目最要紧的一处正确性，见 README 的说明
- **所有卡片长得完全一样**：不做配色、不做「正在上」高亮。上午的课和下午的课、正在上的和还没上的，样式没有任何区别
- 已结束的课右侧显示灰色的「已下课」

### 4. 周课表（左右翻页 + 连堂合并 + 点课看详情）

点底部「周课表」。打开时应**自动定位到本周**（第 6 周），不必手动翻。

| 判据 | 说明 |
| --- | --- |
| 打开就停在第 6 周 | 而不是从第 1 周开始 |
| **左右滑动切周** | 手指左右划，一周一页。往左划到第 7 周、第 8 周……往右划回第 5 周。滑到第 1 周与第 19 周时**划不动**（有回弹） |
| **切周时不回到顶部** | 先把某一周上下滑到看第 10-12 节，再左右划到下一周 —— 新的一周应该**停在同样的纵向位置**，而不是跳回第 1 节 |
| **翻页要跟手** | 手指连续快划十几周，画面应始终跟得上手指（最坏情况是掉几帧，不该出现「手划完了画面才跟上」）。本版为此做了三件事：整页网格线由「每个格子各画一遍」（一页 200 多个绘制节点）改为「整页一条线」；没课的连续节次合并成一段（一页节点从 84 个降到 20 多个）；不再在组合根读页号（否则翻一页要重组整棵树）。若仍明显卡顿，请记下机型 + 卡在哪一步 |
| 顶部标题随翻页变 | 「第 N 周 ⌄」的数字与右侧日期范围（如 `10月5日 - 10月11日`）应随滑动实时更新，松手后停在当页 |
| **连堂课是一个格子** | 高等数学周一 1-2 节应是一个**高两格**的整体圆角卡片，中间**没有横线**、**没有断开**；思想道德与法治周三 3-5 节是一个高三格的卡片 |
| **课程格子是圆角** | 每个课程块四角为 8dp 圆角，四周留白（左右各 1.5dp、上下各 1dp）。留白处能看到下面的 0.5dp 网格线 —— 贴着格子边画圆角会把网格线吃掉半条，所以必须内缩 |
| **网格线是分档的** | 所有线仍然 0.5dp。外框、表头底边、时间轴右沿是**全浓度**；节次分隔线和星期分隔线是同一个颜色冲淡到 0.6（更浅）。相邻两格之间是一条线 + 两侧留白，不是两倍宽的缝 |
| **网格是一张圆角卡片** | 整张网格四周留 8dp、四个外角是 14dp 圆角，外面一圈 0.5dp 的框。8dp 的缝里能看到页面底色；设了图片/渐变背景后，缝里透出来的应是用户自己的背景 |
| **表头和时间轴有淡底** | 日期行和左侧节次栏铺一层极淡的灰（比格内线还浅），课程区是白的。这块底色七天一视同仁，**没有单独标今天** |
| **节次横线不穿过时间轴** | 每一节的横线从时间轴**右边**开始画；时间轴那一栏里只有「第N + 时间」和底色，一条横线都没有 |
| **星期分界线穿过表头** | 一周七天的竖线从卡片最上沿一直画到底，把「三」这个字和它下面那一列对起来；卡片最外侧的左、右两条边由外框负责，不重复画 |
| **外框粗细均匀** | 四个角与四条边看起来一样粗，不该出现「某一边只有一半」——外框路径内缩了半条线宽（`Stroke` 是以路径为中心往两侧各画一半的） |
| **底部不再多一条线** | 网格最下面那一行下沿就是卡片外框，不是「外框 + 一条线」叠出来的双线 |
| **水波纹不出圆角** | 点课程块时，涟漪必须被裁在圆角范围内，四个角不能溢出色块 |
| 同格多门课上下排开，**不合并** | 例如「人工智能通识」周二 6-7 节是 7-8 周在 JX08-102、9-16 周在「机房由教师确认」两条记录（它们在**不同周**，所以在任一周里只看到一条） |
| 左侧时间轴 | 每行显示「第N」+ 该节**开始**和**结束**时刻；第 6 周的 6-7 节应显示 **13:30 / 14:10**（冬令），9 月的周应显示 `14:00 / 14:40`（夏令）。**把系统字号调到最大，三行字仍然各占一行、都完整显示、不折行、不和上下相邻行叠在一起** —— 这一栏会自己变宽（40dp → 最多 72dp），格子高度也跟着字号长（54dp → 最多 86.4dp），右侧 7 天的宽度相应变窄，但课名照旧显示。若在「作息时间」里固定了档位（见 4d），这里的时刻就不再随月份变 |
| **每门课底色不同** | 周课表里**唯一**保留的突出方式：同一门课（如「高等数学B（一）」）在所有周次里都是同一个颜色，不同课颜色不同。颜色由课程名稳定派生，重装或重新导入后不变 |
| **除课程底色外没有任何高亮** | 7 列完全一样 —— **今天那一列不再有淡色底**、表头今天那格也不填色（表头整行那层淡底是「这是标签区」的分区色，左侧时间轴同色，七天一视同仁）。空格子与有课的格子共用同一个底色，只有文字、细线和圆角色块（**没有阴影、没有渐变**，唯一的边框是整张网格最外面那一圈）。顶部工具栏右侧那个「本周」小徽标是导航标记（告诉你现在停在第几周），不属于课程高亮 |
| 顶部「第 N 周 ⌄」按钮 | 点开是 4 列的周次网格，点任意一周跳到那一周；当前周用主色、选中的用浅色 |
| 「回到本周」按钮 | 滑到别的周才出现，点一下回到第 6 周 |
| **右上角有一个「+」** | 就在这一行最右边（「本周」徽标的右侧），一个加号图标。点它是「自己加一节课」，见下面第 4d 节 |
| 第 1 周的日期范围应为 08-31 - 09-06 | 校历第 1 周周一为 2026-08-31 |

### 4b. 点课程看详情

**周课表里点任意一个课程格子**，或**今日课表里点任意一张课程卡片**，都会弹出详情。

以第 6 周周一的高等数学B（一）为例，应看到：

| 字段 | 值 |
| --- | --- |
| 标题 | 只有课名，**不带色块** |
| 时间 | `07:50 - 09:20（第 1-2 节）` |
| 星期 | 周一 |
| 地点 | JX08-109 |
| 教师 | （真实数据里的授课教师） |
| 周次 | `5-18周` |
| 教学班 / 校区 / 课程代码 | 有则显示 |

判据：

- **翻到 10 月的周次，详情里的时间必须是冬令时间**（第 6-7 节显示 `13:30 - 15:00`），翻到 9 月的周次必须是夏令（`14:00 - 14:40` 起）。详情弹窗用的是「这一周属于几月」，不是今天几月 —— 这是最容易错的地方。**把作息档位固定住之后（见 4d），这里就不再随月份变** —— 固定夏令时，10 月那一周的详情也该显示 `14:00 - 15:30`
- 「形势与政策」的周次应显示 `第 7, 15 周` 之类的离散形态，而不是 `1-19周`
- 地点为空的课（例如体育（一））显示「未排地点」
- 自己加的课（见 4d）在「周次」下面会多一行 **`来源 | 自己加的（重新导入课表不会丢）`**，弹窗底部也会多出「修改」「删除」两个按钮；教务导入的课这两种都不该出现
- 点「知道了」或点弹窗外关闭

### 4d. 自己加课（周课表右上角的「+」）与作息档位

这两项都是本版新加的。先做「自己加课」：

1. 进**周课表**，点右上角的「**+**」。
2. 「课程名」随便填一个（比如 `临时调课`），然后：
   - **星期**：7 个按钮，点「三」；
   - **节次**：「第 N 节」两个下拉，选 `第 3 节` 到 `第 4 节`。选完下面会出现一行灰字，显示**该档位下这两个节次的实际钟点**（例如 `09:35 – 11:10`）—— 这行字就是给你核对作息档位的；
   - **周次**：默认是「**整个学期（1-19 周）**」；点「只加几周」会展开一个 7 列的周次网格，点几个格子（旁边有「全选」「清空」和「共 N 周」）；
   - 「地点」「教师」可以不填。
3. 点「**加进课表**」。

判据：

| 判据 | 说明 |
| --- | --- |
| 立刻出现在表里 | 对话框关掉就该在刚才选的那一天、那两节上看到它，**不用重新导入、不用重启** |
| **有一道深色描边** | 自己加的课四周有一圈 1.5dp 的深色边框，教务导入的课没有。这是唯一区分方式 —— 底色仍按课名派生（所以同名课颜色和正式课一样） |
| 只加几周的课只在那几周出现 | 翻到没选的周次，这一格应该是空的；翻回选中的周次又出现 |
| **点开能改** | 点这个格子 → 详情里有「修改」→ 改课名或节次 → 「保存」后表里立刻变 |
| **点开能删** | 详情里点「删除」→ 会先弹一句确认（防止误触）→ 确认后从表里和**上课提醒**里一起消失 |
| **重新导入不会丢** | 回「⋮」→「导入课表 / 重新导入」，用同一个账号重新导入一遍；重新导入完成后，自己加的那节课**仍然在** |
| 换一门课导入也不会丢 | 换另一个学生的账号导入，自己加的课依然在（它跟课表文件是分开存的） |
| 「清除本地数据」会连它一起清 | 那是「清空一切」，自己加的课也会被删掉，且不可恢复 |
| 上课提醒也认它 | 自己加的课到点前同样会弹横幅（前提是那一格的开始时刻能被算出来） |

再做「作息档位」：点「⋮」→「**作息时间（按月份自动切换）**」（括号里会写明当前档位）。

| 判据 | 说明 |
| --- | --- |
| 菜单标题带当前档位 | 不点进去就知道现在在哪一档。默认是「按月份自动切换」 |
| 三个选项 | 「按月份自动切换」「一直用冬令时」「一直用夏令时」，选中的那个是实心圆点 |
| **点一下当场生效，不关框** | 选「一直用夏令时」之后，对话框底部那行小字会立刻从 `13:30–14:10` 变成 `14:00–14:40`（拿的是**第 6 节**，因为第 1-5 节两套表本来就一样，拿第 1 节举例会被当成「点了没反应」） |
| **只影响第 6-12 节** | 固定夏令时之后，1-5 节的时刻一个字都不该变 |
| 时间轴跟着变 | 关掉对话框看周课表左侧时间轴：固定夏令时后，**12 月**的周次第 6 节也该显示 `14:00` |
| 详情跟着变 | 同上，翻到任意周次点开第 6 节的课，详情里的时间也跟着档位走 |
| **提醒跟着变** | 固定夏令时后，第 6 节的提醒时刻应比自动档下 10 月的提醒**晚 30 分钟**（13:30 → 14:00，提前 1 小时就是 12:30 → 13:00）。这一条最容易漏 —— 提醒是 `AlarmManager` 直接拉起来的，不经过界面 |
| 桌面小组件跟着变 | 小组件里显示的今日课程时间也按新档位 |
| **重启后还记得** | 杀掉进程重开，档位仍是刚才选的那个（存在单独的 `season.json` 里） |
| 与「清除本地数据」的关系 | 清除本地数据**不会**重置作息档位（它是显示偏好，不是课表数据） |

### 4c. 全局自定义背景

菜单 →「课表背景」。对话框是半透明的，**拖滑块时能直接看到后面课表在变**，所以没有单独的预览区。

| 模式 | 操作与判据 |
| --- | --- |
| 默认 | 顶层「默认」按钮，回到**纯白底**（浅色主题下就是 `#FFFFFFFF`，即主题的 `surface`） |
| 纯色 | 点「纯色」→ 出现 8 个色块，点任意一个，整个 App 的背景（**含顶栏、底栏、状态栏后面**）立即变色 |
| 渐变 | 点「渐变」→ 出现 6 组两色渐变，每行 3 组；点一组即生效 |
| 图片 | 点「图片」→「选一张图片」→ 从相册选一张 → **弹出「挑显示区域」的框**（见下），确定后整屏铺满该图（不拉伸变形） |
| 重新选择区域 | 已经设过图片时，图片那一行右边多一个「重新选择区域」，点它回到取景框，改完覆盖原来的区域 |
| 遮罩 | 选过纯色/渐变/图片后出现「背景遮罩 N%」滑块，范围 0–80%。**默认 0%（不压暗）**，拖到 80 时最暗（**上限 80%，防止调到全黑等于白设**） |
| 恢复默认 | 选过之后底部出现「恢复默认背景」按钮 |

**「挑显示区域」的框（选完图必现）：**

| 操作 | 预期 |
| --- | --- |
| 长什么样 | 一个和屏幕同比例的取景框，图铺在下面；框内就是最终背景，框外压暗 |
| 单指拖动 | 图跟着手指走，**拖不出界**（到边就停住，不会露出空白） |
| 双指缩放 / 拖缩放滑块 | 放大缩小，同样不会缩到露白；滑块范围 1×–6× |
| 点「重置」 | 回到居中、1×（也就是整张图按屏幕比例居中裁剪） |
| 点「取消」 | **背景一个字都不变** —— 原来没设图的还是没设，原来设过图的仍是原来那张、原来那个区域 |
| 点「确定」 | 框里看到什么，背景就是什么 |
| 再点「重新选择区域」 | 进来时**看到的是上次挑的那一块**（视角能原样还原），不是回到居中 |
| 转屏 / 换一台比例不同的手机 | 挑好的那块区域还在，只是按新比例重新居中（**多裁一点，但绝不拉伸变形**） |

**关键判据（这个功能最容易做成「设了等于没设」）：**

- **没选任何背景时，课表底是纯白 `#FFFFFF`**，不带任何灰调/蓝调；顶栏、底栏、卡片、课程区也都是同一个白，只用 0.5dp 细线分格（表头行和左侧时间轴另外铺一层极淡的分区底色）
- **刚选完颜色/图片时，遮罩显示的是 0%**，颜色和图片是原样的亮度 —— 不该一上来就被压暗（要压暗得自己拖滑块）。**换一张图片时遮罩也回到 0%**
- **界面固定浅色主题，永远是白底**：把手机的「深色模式」打开/关掉，App 的底色、状态栏图标都不应该跟着变（状态栏图标始终是深色）。这条是刻意钉死的 —— 若跟随系统变成深色，状态栏图标却仍按浅色主题算，就会糊在底色上看不见
- 冷启动时不该闪出别的底色（`android:windowBackground` 已对齐成同一个白；深色主题的对齐值在 `values-night/colors.xml`，只影响系统深色模式下 App 启动前的那一帧）
- 设了背景之后，**顶部标题栏、底部导航栏、今日课表的卡片都应该透出背景**，而不是一块块不透明的白/灰把背景切碎
- **周课表整张网格连底色都没有**：没课的格子应该直接看到背景原图本身（不是隔着一层白、也不是隔着一层 90% 白的半透明），表里只剩线。整张表靠四周那 8dp 留边 + 一圈 0.5dp 外框 + 内部细线交代边界
- **表头（日期行）和左侧时间轴仍是那层 0.7 的淡灰底**（这是「标签区」，得保证日期和节次在任何背景上都读得出来）；把它和课表格子区分开看
- **课程格子的颜色不参与半透明**：课表格子仍是实色（不然课名会看不清）
- **不设自定义背景时（默认纯白），周课表的观感必须和以前一模一样** —— 空格子那里不能缺一块、不能发灰，整页应该还是均匀的白
- 选图片后**把相册里的原图删掉，背景仍然在**（图片已被复制进 App 私有目录）
- 选图片后**杀掉 App 再打开**，背景还在；**重启手机**后仍在
- **挑完区域后杀掉 App 再打开，显示的还是挑过的那一块**（不是回到居中）；点「重新选择区域」进去，视角也应还原成上次那一块
- **挑区域时点「取消」，不该多出一张图**：取消后连点几次「选一张图片」再取消，App 占用的空间不应一直涨（新导入的图在取消时会被删掉；「重新选择区域」取消时则必须保留原图）
- **选了图片却不该变成一片纯白**：选一张系统相册里解不出来的图（例如部分机型默认拍照产出的 HEIC），应当直接提示「这张图读不出来，换一张试试（可能是 HEIC 格式，或文件太大）」，**背景保持原样**。若这一步提示了、背景却没变，就说明白名单生效了；若没提示、整屏变成纯白，才是 bug
- 换成纯色后，之前的图片文件应被清掉（不占空间）
- 选一张超过 12MB 的图，应提示「这张图读不出来，换一张试试（可能是 HEIC 格式，或文件太大）」，而不是无声失败


### 5. 上课提醒（提前 10 / 20 / 30 分钟、1 小时或 2 小时弹横幅）

导入成功并授予通知权限后，系统里会排好未来 7 天每节课的提醒。提醒的目标是**像 QQ / 微信消息那样从屏幕顶部弹出来**（Android 叫 heads-up 横幅），而不是安静地躺在通知栏里。

**先做这一步：验证横幅真的弹得出来。** 菜单 →「上课提醒」→ 点「发测试横幅」。

面板最上面是**提前量**：五个胶囊按钮「10 分钟 / 20 分钟 / 30 分钟 / 1 小时 / 2 小时」，默认「1 小时」。

| 判据 | 说明 |
| --- | --- |
| 点某一档 | 立刻选中；面板顶部那句说明跟着变（「每节课开始前 2 小时，会像 QQ、微信消息那样…」） |
| 改完立刻生效 | **改完不需要重新导入课表**：已经排出去的那批闹钟会整体重排 |
| 杀掉 App 再打开 | 选中的那一档还在（存在 `filesDir/reminder.json`） |
| 早课不跨天 | 选「2 小时」时，早上第 1 节（07:50）的提醒是**当天 05:50**，不会跑到前一天 |

| 面板里那一行的状态 | 含义 | 点击右边的按钮会跳到哪里 |
| --- | --- | --- |
| `✓ 通知权限 已允许` | 通知总开关开着 | 本应用的通知设置 |
| `✕ 通知权限 被关掉了` | 通知发不出去，也不会有横幅 | 同上（Android 7 上退到应用详情页） |
| `✓ 提醒样式 横幅提醒（推荐）` | 渠道重要性 ≥ 高，会弹横幅 | 该渠道的设置页 |
| `✕ 提醒样式 静音，只进通知栏，不弹横幅` | 渠道被改成「静音」了 | 同上，把重要性改回「紧急 / 高」 |
| `✕ 提醒样式 有提示音，但不弹横幅` | 渠道是「默认」档，只响不弹 | 同上 |
| `✓ 电池优化 已放行` | 闹钟不会被省电策略拖延 | 系统的电池优化确认对话框 |
| `✕ 电池优化 未放行` | 省电模式下提醒可能晚几十分钟 | 同上 |
| `✓ 精确闹钟 已允许` | 到点准时（Android 12+ 才有这一行） | 「闹钟和提醒」权限页 |
| `✕ 精确闹钟 未允许` | 可能晚几分钟，**不影响弹不弹横幅** | 同上 |
| `• 自启动 / 后台运行` | **系统不提供检测接口**，只能手动确认 | 按厂商跳到自启动白名单页（小米 / 华为 / 荣耀 / OPPO / 一加 / realme / vivo / iQOO / 魅族 / 三星 / 华硕 / 诺基亚 / 乐视 / 锤子），跳不过去退到应用详情页 |

> 点「去设置」跳走时**面板不会关**，改完返回会自动重新检测 —— 不用手动关掉再打开。

| 判据 | 说明 |
| --- | --- |
| 测试横幅 | 从屏幕顶部弹出来，标题「测试提醒：横幅弹出来了吗？」；下拉可以看展开后的完整说明 |
| 通知标题 | 「还有 1 小时上课」（默认档）；换成 30 分钟就是「还有 30 分钟上课」，换成 2 小时就是「还有 2 小时上课」|
| 通知正文 | 形如 `《高等数学B（一）》 07:50-09:20 · JX08-109`（没有地点时写「地点待定」）；**刻意不写教师名**，横幅第二行会被截断 |
| 下拉展开 | 三行：`《课名》` / `07:50 - 09:20 · 第 4-5 节` / `JX08-109 · 张明远` |
| 时机（默认 1 小时） | 10 月 8 日周四应有两条：高等数学B（一）**06:50**、工程制图基础**12:30**（都是冬令时间减 1 小时） |
| 时机（换成 10 分钟） | 同样两条，变成 **07:40** 与 **13:20**；条数一条不少，只是整体平移 |
| 时机（换成 2 小时） | 变成 **05:50** 与 **11:30**（仍在当天） |
| 夏令/冬令 | 9 月同一节课的提醒应早于 10 月 1 日之后的（第 6 节从 14:00 变 13:30，提醒从 13:00 变 12:30）。在「作息时间」里固定成夏令之后，10 月那一条也该是 13:00，不再跟着月份走 |
| 不排不该上的课 | 第 6 周**不应**收到「人工智能通识」（7-16 周）或「形势与政策」（仅 7、15 周）的提醒 |
| 只排 7 天 | 不用等满一学期验证；隔天再看，窗口应往后滚了一天（由每日闹钟驱动，受系统省电策略影响可能延后） |
| 通知权限被关时 | 菜单里显示「上课提醒（通知已关闭）」；点「发测试横幅」会提示「通知被系统关掉了…」而不是假装发出去了 |
| 锁屏可见 | 锁屏上应直接显示课名与地点（渠道锁屏可见性是 PUBLIC），而不是「一条通知」 |
| 改时间/换时区后 | 手动改系统时间或时区，已排的提醒会按新的本地时间重排（`TIME_SET` / `TIMEZONE_CHANGED`） |
| 手动触发验证的小技巧 | 想立刻看到效果，可把手机时间调到某节课前 1 小时零几分（例如 10 月 8 日 12:35），然后**改一下提前量**（改动会触发重排），等一两分钟 |
| 改提前量后不重导 | **改成「10 分钟」，然后什么都不做**：次日那条提醒必须按新的提前量来（不重排的话会照旧提前 1 小时弹 —— 那才是 bug） |

> **横幅弹不出来时最常见的三个原因**（按概率排序）：① 渠道被系统或用户改成了「静音」；② 系统里本应用的「悬浮通知 / 横幅通知」开关没打开（各家叫法不同，小米叫「悬浮通知」，华为叫「横幅通知」）；③ 国产 ROM 把应用清理后收不到闹钟广播，需要加入自启动白名单。
>
> 第 3 条是「完全不提醒」而不是「不弹横幅」—— 表现为 App 打开着就能弹，清理后台后就不弹了。

## 五、已知限制

这些是**有意为之**的范围收敛，不是 bug：

- 不做 ICS 日历导出
- 不支持多学期切换（只导入并显示当前学期；换学期需重新导入）
- 不支持手动增删改课
- 不做主题换色，**主题钉死浅色**（不跟随系统深色模式，理由见 README）
- 提醒提前量只提供 **5 档**（10 / 20 / 30 分钟、1 小时、2 小时），不能填任意分钟数
- 提醒只排未来 **7 天**（每天自动往后滚一天），所以「改系统时间到很远以后」不会看到提醒
- **不处理登录验证码**：如果学校要求验证码，App 会直接提示「需要验证码，请先到网页端登录」并中止，绝不盲目提交（避免计入 5 次锁定）
- 小组件跨天刷新用的是非精确闹钟，触发可能有几分钟到十几分钟延迟
- 上课提醒**优先用精确闹钟**；如果 Android 12+ 上没给 `SCHEDULE_EXACT_ALARM`（targetSdk 33+ 默认不给，需要用户去设置里放行），会自动退回非精确闹钟 —— 提醒晚几分钟，但一定会发
- 「自启动 / 后台运行」这一项**系统不提供检测接口**，面板上只能显示中性的 `•`，需要用户自己确认
- 能不能由 App 主动把小组件放上桌面，**取决于启动器而不是机型**（同一台手机换个桌面 App，结果就可能从「能」变成「不能」）。不支持时只能按面板里的步骤手动添加，这是系统限制，不是没适配
- 崩溃报告**最多保留 10 份**，更旧的自动删（都在 App 私有目录 `filesDir/crash/`，卸载 App 一并清除）
- 崩溃报告**抓不到两类崩溃**：C/C++ 层崩溃（系统写在 `/data/tombstones`，没有 root 读不到）和 ANR（应用无响应，系统写在「开发者选项 → 错误报告」里）。面板底部写明了这两条，不假装全都能抓
- **教务域名是写死的**，不跟随 `portal` 之类入口页的重定向。如果哪天学校换了教务域名（正方升级、换供应商），需要更新 `core/CasAuthenticator.kt` 里的 `AUTH_BASE` / `JW_BASE` / `SERVICE_PATH`
- **学期是逐个试出来的，不是从教务系统读来的**。课表页上默认选中的 `xnm`/`xqm` 不可信（实测遇到过服务端把上一学年的第 2 学期渲染成选中状态），服务端也没有一个可信的「当前学期」字段。所以导入顺序是「按本机日期算出的当前学期 → 页面默认值 → 同学年另一学期 → 上一学年第二学期 → 上一学年第一学期」。**代价：新学期还没排课时会显示上一学期的课表。** 导入与刷新的提示里都会写出最终用的学期名，看到不对就等学校排完课再刷新一次
- 学期候选依赖**本机日期**。手机日期错了（或者时区不在中国），算出来的「当前学期」就会错 —— 不过候选里还有页面默认值与上一学年两个学期兜底，通常会试中。这是一处**有意接受的取舍**：与其信一个已知不可信的页面默认值，不如按日期猜个最可能的、再逐个退

## 六、无法自动验证的部分

本项目开发环境**没有安卓模拟器也没有连接真机**，所以以下内容只经过静态检查与单元测试，没有被真正运行过：

- 所有 Compose 界面的实际渲染效果与布局（窄屏下 7 列课表会不会挤、连堂格子里课名会不会被截断、登录页渐变与键盘弹出后的滚动、提醒自检面板在小屏上会不会溢出）
- 小组件在真实启动器上的渲染（RemoteViews 的样式支持与 App 内 Compose 不同）
- **小组件在 OPPO / 一加 / vivo / 华为上的实际添加行为**：面板里的手动路径、`requestPinAppWidget` 各家弹不弹框、以及「加完数一遍」这个判断，全部依据的是各家文档与社区实测记录，**本机没有这些机型**。`manualSteps` 的文案有单元测试钉住（`WidgetPinnerManualStepsTest`，11 个），但「照着这几步能不能真的找到入口」只能在对应机器上确认
- **组件选择器里的预览图**：`previewLayout` 与 `previewImage` 都已打进包（已用 aapt2 确认 `res/layout/widget_preview.xml` 与 `res/drawable-nodpi-v4/widget_preview.png` 都在 APK 里），但**系统组件选择器把它画成什么样、Android 12 与 11 分别取哪一份**，只能上真机看
- **崩溃报告这条链路**：「模拟一次崩溃记录」走的是和真崩溃完全相同的写盘函数，但**真·未捕获异常能不能被拦到、报告写完再委托给系统处理器之后崩溃弹窗是否照旧**，没有在真机上崩过。另外 `CrashStore` 的 10 份上限、`.tmp` 再 rename 的原子写都只过了单元测试
- **导出分享**：`FileProvider` 的 authority 已用 aapt2 确认是 `com.ntu.schedule.debug.fileprovider`（跟着 `${applicationId}` 走，所以 debug 包名带 `.debug` 也正确），`file_paths.xml` 也只开了 `crash/` 一个目录；但**分享到微信 / 邮件之后对方能不能正常打开**、各家分享面板会不会因为 `text/plain` 而拒绝，没有实测过
- **左右翻页的手感**：已针对掉帧做了专项优化（见第 4 节的判据表），但**改完只在编译层面验证过，没有被真正划过** —— 优化是否够用、低端机上还剩多少顿挫，只有在真机上划才能判断
- **固定浅色主题**：`darkTheme = false` 与 `SystemBarStyle.light(...)` 都已编译通过，但「系统开深色模式时 App 仍是白底、状态栏图标仍是深色」这件事没有在真机上确认过
- **自定义背景的实际观感**：图片的裁剪位置是否合适、半透明面板（`panelColor(0.9f)`）叠加背景后文字对比度够不够、遮罩拖到多少才舒服（**默认 0%，要压暗得自己拖** —— 这个「多少才够」只有你自己看才准）
- **挑显示区域那个框的手感**：「拖不出界」的夹取逻辑有单元测试钉着（`ImageCropTest` 穷举了 10 种图尺寸 × 6 种视口比例 × 7 种区域），但**拖起来跟不跟手、双指缩放会不会和系统返回手势打架、窄屏上缩放滑块会不会挤**，只能在真机上划才知道
- **「选了图片解不出来」这条兜底**：`AppearanceStore.decodable()` 用的是 `BitmapFactory.inJustDecodeBounds`，逻辑本身很确定，但**手上没有 HEIC 样本、也没有 API 24–27 的真机**，所以「HEIC 会被拒掉」这句话是推断（依据是 HEIF 解码从 API 28 才有），没有实测过
- 相册选图：用的是最朴素的 `ACTION_GET_CONTENT`（`PickVisualMedia` 在 API 24–29 上没有，各家 ROM 的相册选择器行为不一致），**各家 ROM 返回的 `content://` URI 形态不同，只在真机上验证过**
- **横幅到底弹不弹得出来**：渠道重要性、声音/震动、锁屏可见性这三条已按官方条件逐条落实，但「弹出来」本身是系统行为，只能在真机上用「发测试横幅」按钮确认
- **各厂商自启动页的 ComponentName**：`OemSettings` 里每个厂商给了多个候选（同一品牌不同系统版本换过包名类名），逐个试、打不开就退到应用详情页；这些类名**只在对应机型上才能验证**，本机无法验证
- **Android Keystore 加解密**：`SecretStore` 依赖真实设备的密钥库，在 JVM 单元测试里跑不到，所以「记住账号密码」这条路径没有被自动测试覆盖（拿不到密钥库时会置灰开关，这条降级逻辑是有意保留的兜底）
- 端到端登录（Kotlin 侧）—— 登录协议本身已在 Node 侧用真实账号验证通过（统一身份认证 CAS → 跳回教务），Kotlin 实现与 Node 实现通过固定向量测试保证 AES 部分逐字节一致，但**完整的 Kotlin 登录链路尚未跑过真实服务器**
- **自动试学期这条链路**：`TermPicker` 的候选顺序与边界（时区、9 月起点、去重、上限）由 `TermPickerTest` 14 个用例钉死；「某学期是不是真的有课」只有服务器知道，`TermPicker` 本身**不判断也不缓存结果**。所以「用页面默认值查是 0 条、换一个学期查就有课」这个结论来自 **Node 侧用真实账号跑出来的抓包数据**，不是 Android 侧实测；Kotlin 实现只是照着同一组接口参数重放
- **导入提示里的学期名**：只是把 `ScheduleParser` 从接口响应里读出来的 `XNM`+`XQM` 拼成人话。因为这两个字段是**原样回显查询参数**的，所以提示里写的学期名一定等于「这次请求用的学期」—— 这一点是确定的；但**提示在窄屏上会不会被截断**（「导入成功，共 N 条课程安排（2026-2027 学年 第 1 学期）」比原来长了不少）只能在真机上看
